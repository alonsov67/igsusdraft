Validar Bundle

POST /fhir/$validate · Conceptual; demostrado localmente con HL7 Validator CLI

Canonical URL: https://fhir.sus-rda-mx.localVersion: 0.3.0Draft as of: 2026-10-07Computable Name: RIPSRDAMX
PROVISIONAL · datos sintéticos. Esta guía experimental no es un estándar oficial mexicano. México/SUS es el único dominio objetivo; Colombia se conserva exclusivamente como REFERENCE_PATTERN. No contiene PHI/PII.

Propósito

Validar Bundle documenta una capacidad PROVISIONAL para México/SUS con datos sintéticos. No declara estándar oficial mexicano ni endpoint productivo.

Errores esperados

  • 400 recurso no parseable
  • 422 falla de perfil, referencia o terminología
  • 403 actor no autorizado

OperationOutcome cuando aplica

Las fallas de parseo, perfil, terminología, autorización o contrato deben representarse como OperationOutcome cuando la interacción sea FHIR o cuando la fachada operacional necesite devolver un diagnóstico interoperable.

Seguridad esperada

No persistir payload durante validación aislada; no registrar cuerpos ni identificadores sensibles.

Trazabilidad

Puede generar evento operacional de validación, sin persistir el recurso como aceptado.

Ejemplo response

{
  "resourceType": "OperationOutcome",
  "issue": [
    {
      "severity": "error",
      "code": "structure",
      "diagnostics": "Bundle no conforme al perfil esperado"
    }
  ]
}

Restricciones

  • Validar no equivale a radicar.
  • Validar no crea radicado.
  • Validar no confirma responsable financiero final.
  • La ruta documentada preferente es /fhir/$validate; variantes específicas por tipo permanecen PROVISIONAL.

Resumen para implementadores

Separar validación de conformidad FHIR del workflow operacional y de reglas SUS.
