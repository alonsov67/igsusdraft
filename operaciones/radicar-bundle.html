Propósito

Radicar paquete FHIR documenta una capacidad PROVISIONAL para México/SUS con datos sintéticos. No declara estándar oficial mexicano ni endpoint productivo.

Errores esperados

  • 400 Bundle inválido
  • 422 referencias o perfiles no conformes
  • 409 idempotencia/radicado duplicado
  • 403 actor no autorizado

OperationOutcome cuando aplica

Las fallas de parseo, perfil, terminología, autorización o contrato deben representarse como OperationOutcome cuando la interacción sea FHIR o cuando la fachada operacional necesite devolver un diagnóstico interoperable.

Seguridad esperada

Autenticación institucional, autorización por organización, minimización y no registro de cuerpos FHIR.

Trazabilidad

Genera radicado operacional, timeline, Provenance/AuditEvent cuando aplique y referencia al Bundle aceptado.

Ejemplos request/response

Ejemplo request

{
  "resourceType": "Bundle",
  "meta": {
    "profile": [
      "https://fhir.sus-rda-mx.local/StructureDefinition/sus-cross-care-bundle"
    ]
  },
  "type": "collection",
  "entry": [
    {
      "resource": {
        "resourceType": "Claim",
        "identifier": [
          {
            "value": "RAD-SINT-001"
          }
        ]
      }
    }
  ]
}

Ejemplo response

{
  "resourceType": "OperationOutcome",
  "issue": [
    {
      "severity": "information",
      "code": "informational",
      "diagnostics": "Radicación sintética aceptada: RAD-SINT-001"
    }

}

Restricciones

  • La radicación se envía a la Cámara de Compensación; no es envío directo a IMSS.
  • No contiene unitPrice, net ni total.
  • No contiene CFDI.
  • No contiene pago ni evidencia de pago.
  • La valoración económica ocurre después.
  • Coverage.payor no confirma responsable financiero final.

Resumen para implementadores

Usar para radicar el paquete mínimo FHIR ante la Cámara. No mezclar con liquidación, pago, CFDI ni consulta directa a institución responsable.
